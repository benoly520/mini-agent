# 001 需求规格（What & Why）

> SDD 第 1 步：先说清楚「要做什么」，不谈怎么做。
> 本文档是这个项目的**唯一需求来源**。任何实现与本文冲突，以本文为准。

## 1. 背景

从 0 学习 AI Agent 开发，不借助 LangChain / LlamaIndex / 官方 SDK 等任何框架，
亲手实现一个能运行在本地终端的最小智能体（mini-agent），并通过它真正理解：

- 大模型是怎么被调用的（HTTP + 流式）
- 模型怎么「决定」去调用外部工具
- Agent 的「循环」到底循环了什么
- 工具结果怎么回灌给模型并生成最终回答

## 2. 一句话目标

在终端里输入自然语言，Agent 能自主调用工具获取真实数据并回答。
示例：输入「明天天气」，输出我所在地明天的真实天气预报。

## 3. 名词解释（给小白）

| 名词 | 大白话 |
| --- | --- |
| LLM | 大语言模型，就是 ChatGPT 背后那个东西。它本身**不能上网、不知道实时信息** |
| 工具调用 / function calling | 让模型输出一段结构化 JSON，说「我要调用 `get_weather`，参数是 `{city:"北京"}`」，由**你的代码**去真正执行 |
| Agent 循环 / loop | 反复执行：模型思考 → 要工具 → 你执行 → 结果喂回模型 → 模型再思考 …… 直到它给出最终答案 |
| SSE 流式 | 服务端一个字一个字往回推，所以你能看到回答「打字机」式出现 |
| token | 计费单位，也是上下文上限单位。约等于 1.5 个汉字 |

**关键认知**：模型不会真的去查天气。它只会「说」要调用什么工具，
真正干活的是你写的普通 TypeScript 函数。这是理解 Agent 的第一道门槛。

## 4. 用户故事

| 编号 | 用户故事 | 优先级 |
| --- | --- | --- |
| US-1 | 我在终端启动程序，能持续对话，而不是问一句就退出 | P0 |
| US-2 | 我输入「明天天气」，它先自己判断我在哪，再查天气，最后用中文回答我 | P0 |
| US-3 | 我能看到它正在调用哪个工具、传了什么参数，过程透明 | P0 |
| US-4 | 回答是流式逐字出现的 | P1 |
| US-5 | 我输入 `/clear` 能清空上下文，`/exit` 能退出 | P1 |
| US-6 | 模型说错参数（比如城市名不存在）时，它能自己纠错重试 | P2 |

## 5. 功能需求

### P0（第一版必须有）

- **FR-1 终端交互循环**：程序启动后进入 REPL，持续读取用户输入，支持多轮对话。
- **FR-2 LLM 调用**：通过 OpenAI 兼容的 `/chat/completions` 接口调用模型，
  使用原生 `fetch`，不引入任何 SDK。
- **FR-3 工具注册表**：用统一的 `{ name, description, parameters }` 结构声明工具，
  并能按名字分发执行。
- **FR-4 Agent 循环**：最多循环 5 轮（`maxSteps`），模型不再要求调用工具时立即结束。
- **FR-5 定位工具** `get_my_location`：根据公网 IP 推断用户所在城市。
  按 `ipapi.co` → `wttr.in` 顺序多源探测；全部失败时报错，由模型反问用户城市。
  **不允许**用「环境变量里写死一个默认城市」的方式兜底。
- **FR-6 天气工具** `get_weather`：入参 `city`、`date_offset`（0=今天,1=明天,2=后天），
  返回该城市当天的天气描述、最高/最低温、降水概率。
- **FR-7 工具轨迹打印**：每次工具调用在终端打印 `[工具] 名称 + 参数` 与返回结果摘要。

### P1（第一版做完再加）

- **FR-8 流式输出**：逐字渲染模型回答。
- **FR-9 会话记忆**：多轮对话共享 `messages` 历史。
- **FR-10 斜杠命令**：`/clear` 重置上下文，`/exit` 退出。

### P2（后续迭代）

- **FR-11 工具报错回灌**：工具抛错时不崩溃，把错误文本作为工具结果返回给模型，让它自行修正。
- **FR-12 上下文裁剪**：历史消息超过阈值时丢弃最早的部分（见 `003-tasks.md` 阶段 5）。

## 6. 非功能需求

- **NFR-1 零框架**：`dependencies` 必须为空。禁止出现 `langchain`、`openai`、
  `@anthropic-ai/*`、`ai`（Vercel AI SDK）、`llamaindex` 等任何 agent/LLM 框架。
- **NFR-2 零安装可跑**：npm 包数 = 0，`node src/index.ts` 即可运行
  （依赖 Node ≥ 22.18 的原生 TypeScript 支持）。
- **NFR-3 可读性**：单个源文件 ≤ 150 行；关键逻辑必须有中文 JSDoc；缩进 2 空格、单引号。
- **NFR-4 安全**：不执行任意 shell 命令；API Key 只能来自环境变量，禁止硬编码、禁止提交。
- **NFR-5 可观测**：任何时刻都能通过终端输出还原「模型说了什么 → 调了什么工具 → 结果是什么」。

## 7. 验收标准（Acceptance Criteria）

用 Given / When / Then 描述，可直接照着逐条测试。

**AC-1 基础对话**
- Given 已配置 API Key 并启动程序
- When 输入「你好，用一句话介绍你自己」
- Then 终端流式输出中文回答，且不触发任何工具调用

**AC-2 核心场景（本项目最重要的验收）**
- Given 已启动程序
- When 输入「明天天气」
- Then 依次发生：
  1. 终端打印调用 `get_my_location`（无参数或空参数）
  2. 终端打印调用 `get_weather`，其 `city` 参数等于定位到的城市
  3. 终端输出一段自然语言，包含该城市名、「明天」、温度数值和天气描述
- 且最终回答**没有编造**：温度数值必须能在 Open-Meteo 真实数据中对应上

**AC-3 多轮记忆**
- Given 上一轮刚问过「明天天气」
- When 再输入「那后天呢」
- Then 它能复用上一轮的城市，直接调用 `get_weather` 且 `date_offset=2`

**AC-4 工具报错不崩溃**
- Given 程序已启动
- When 输入「查一下 Noizeland 的天气」
- Then 程序不退出；终端能看到工具返回的错误信息；模型给出「查不到该城市」之类的回答

> 注意：别用「火星」当反例——Open-Meteo 的地理库里真的存在同名地点，
> 会返回一份"合法"天气数据。验收错误路径要用现实中不存在的名字。

**AC-5 循环上限**
- Given `maxSteps` 为 5
- When 模型连续 5 轮仍要求调用工具
- Then 循环强制终止，程序不卡死，并提示「已达最大轮次」

**AC-6 无 Key 保护**
- Given 未配置 `LLM_API_KEY`
- When 启动程序
- Then 立刻给出中文提示「请先在 .env 中填写 LLM_API_KEY」，而不是抛出堆栈

## 8. 明确不做（Out of Scope）

先划清边界，避免学习目标被稀释：

- 不做多 Agent / 子 Agent 编排
- 不做 RAG、向量库、知识库
- 不做 TUI 界面（ink / blessed），只用 `readline` 文本交互
- 不做 Web 服务、不做前后端分离
- 不做流式思考过程（reasoning）展示
- 不做工具权限确认弹窗（等有写文件/执行命令类工具时再加，见 `003-tasks.md` 阶段 6）
- 不追求跨厂商兼容（先只对接一个 OpenAI 兼容端点，换模型只改环境变量）

## 9. 外部依赖（都是免费、免注册的公开 HTTP 接口）

| 用途 | 接口 | 是否需要 Key |
| --- | --- | --- |
| 模型推理 | 智谱 `https://open.bigmodel.cn/api/paas/v4`，模型 `glm-4.5-flash`（免费档） | **需要** |
| IP 定位 | `https://ipapi.co/json/` | 否 |
| 城市转经纬度 | `https://geocoding-api.open-meteo.com/v1/search` | 否 |
| 天气预报 | `https://api.open-meteo.com/v1/forecast` | 否 |
