# 004 CLI 形态（怎么把 core 显示到终端）

> 核心原理（协议、循环、流式解析）见 `002-design.md`。
> 本文只讲**交互层**：一个套在 core 外面最薄的壳。
> 与 `005-web.md` 对称——两者是同一个核心的两种外壳。

## 1. 职责边界

cli 只做三件事：读输入、转交给 core、把事件画出来。

| 允许 | 禁止 |
| --- | --- |
| `readline` 读一行输入 | 自己拼 `messages` 数组 |
| 渲染 `AgentEvent` | 判断要不要调工具 |
| 斜杠命令、退出处理 | 发 HTTP 请求、解析天气数据 |

**判定标准**：删掉整个 `code/cli/` 目录，core 依然完整可用
（`code/web/` 的存在就是证明）。

## 2. 启动

```bash
cd code/cli
node src/index.ts
```

- 配置在上一级 `code/.env`，由 `core/src/env.ts` 自动加载，**不需要** `--env-file`
- 要求 Node ≥ 22.18（直接运行 `.ts`，不需要 `npm install`，也不需要 `tsx`）
- `pnpm start` 等价，脚本就是这一条命令
- 换端口/换模型只改 `code/.env`，代码不动

## 3. 主循环

一个 `while` + 一个 `question()`，没有花哨的东西：

```ts
const history = createSession();

while (true) {
  const input = (await rl.question('\n你 > ')).trim();
  if (input === '/exit') break;
  if (input === '/clear') { reset(history); continue; }
  await runAgent(history, input, (e) => renderer.handle(e));
}
```

关键点：`history` 在循环外创建并持续传递，这就是「多轮记忆」的全部实现。
模型本身没有记忆，它每次只是看到了更长的 `messages`。

## 4. 事件到终端的映射

core 通过 `onEvent` 抛出四类事件，cli 的决定非常机械：

| 事件 | 终端表现 |
| --- | --- |
| `step` | 忽略（留给未来的进度提示） |
| `text` | `process.stdout.write(chunk)` 逐字输出，不换行 |
| `tool-start` | `  -> 调用 get_weather({"city":"北京"})` |
| `tool-end` | `  <- 结果 北京 ... 小幅截断显示` |

**一个必须处理的细节**：模型可能先输出一段话，再发起工具调用。
如果直接打印，`-> 调用` 会粘在句尾。所以渲染器维护 `wroteText` 标记，
在打印工具行之前补一个换行。

```ts
if (event.type === 'tool-start') {
  if (wroteText) { stdout.write('\n'); wroteText = false; }
  stdout.write(`  -> 调用 ${event.name}(${event.args || '{}'})\n`);
}
```

## 5. 斜杠命令

| 输入 | 实现 | 注意 |
| --- | --- | --- |
| `/exit` | `break` 出循环 | 用 `break` 而不是 `process.exit()`，让 readline 正常关闭 |
| `/clear` | `history.length = 0` 后重新 push system 消息 | 只清数组，不重建对象引用，否则循环里的 `history` 会指向旧数组 |

`/clear` 那行是新手最容易写错的地方：`history = createSession()` 会**替换引用**，
但循环里拿的还是老变量。正确做法是原地清空。

## 6. 为什么不做 TUI

决策记录（`001-requirements.md` §8 已列为不做）：

- `ink` / `blessed` 会占掉整个学习周期的 80% 时间
- 它们解决的是「界面好看」，而本项目的目标是「看懂 agent」
- 想加界面的人应该去读 `005-web.md`，那才是更适合练手的第二种形态

## 7. 诊断技巧

出问题时的排查顺序，比加日志更快：

1. 模型不调工具、直接编答案 → 检查 `tools` 字段是否真的传了（`002-design.md` §6）
2. 工具调了但参数是空的 → 检查流式 `tool_calls` 是否按 `index` 累加（§3 的坑）
3. 第二轮报 `tool_calls must be followed by tool messages` → 检查 assistant 消息有没有回传（§4 的坑）
4. 回答断断续续或乱码 → 检查 SSE 缓冲区与 `decode(..., { stream: true })`（§5 的坑）

## 8. 验收

沿用 `001-requirements.md` 的 AC-1 ~ AC-6，逐条在终端里跑一遍即可。
与 web 版的差异只在「显示方式」，agent 行为必须完全一致。
