# 文档索引

本项目用 SDD（Spec-Driven Development）：**先把要做什么写清楚，再写代码**。
文档分两层，读的时候不要混。

## 启动命令

| 形态 | 命令 | 打开 |
| --- | --- | --- |
| CLI | `cd code/cli && pnpm start` | 终端里直接对话 |
| Web | `cd code/web && pnpm start` | http://localhost:3000 |

`pnpm start` / `npm start` / `node src/index.ts` 三种方式等价。

前提：**Node ≥ 22.18**；`code/.env` 里有 `LLM_API_KEY`（文件不存在时才从
`code/.env.example` 复制一份再填，已存在切勿覆盖）。
两种形态共用同一份配置、同一套核心，行为完全一致。

## 第一层：核心（与交互形态无关）

| 编号 | 文档 | 回答什么问题 |
| --- | --- | --- |
| 001 | [requirements](./001-requirements.md) | 要做什么、怎么算做完（含验收标准） |
| 002 | [design](./002-design.md) | 怎么做、有哪些必踩的坑 |
| 003 | [tasks](./003-tasks.md) | 按什么顺序做，每步学到什么 |

这三种文档换了界面也不会变，所以排在前面。

## 第二层：形态（同一个核心的不同外壳）

| 编号 | 文档 | 对应目录 | 负责什么 |
| --- | --- | --- | --- |
| 004 | [cli](./004-cli.md) | `code/cli/` | 读输入、把事件打印到终端 |
| 005 | [web](./005-web.md) | `code/web/` | 用 SSE 把事件推给浏览器 |

两者是**平级**关系，不是「客户端 / 服务端」。共同依赖 `code/core/`。

## 阅读顺序

- **从 0 学 agent**：001 → 002 → 003，然后照 003 的阶段动手写
- **只想加个界面**：002 的 §7（模块职责）+ 对应的形态文档
- **改 agent 行为**：先看 002，再改 `code/core/`，两个外壳自动同步

## 为什么这样分

```
001-003   描述「agent 怎么工作」   ← 界面无关
004-005   描述「事件怎么显示」     ← 各自独立
```

一个改动落在哪一层，决定了它要不要写文档：
改协议、改循环 → 动 001/002；改某个界面的显示 → 只动 004 或 005。
