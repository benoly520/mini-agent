# 005 Web 版规格（What & How）

> SDD 第 5 篇（形态层）。CLI 版验证过的核心逻辑，换一种交互形态复用。
> 本文只描述**与 CLI 的差异**：agent 原理见 `002-design.md`，终端形态见 `004-cli.md`。

## 1. 目标

同一套 agent 核心，在浏览器里可用：输入问题 → 实时看到工具调用 → 流式看到回答。

**不是重写，是复用。** CLI 版改一行核心逻辑都不需要。

## 2. 架构

```
浏览器（原生 JS）
   │  POST /api/chat  { message }
   │  ◄──── SSE: text / tool / error / done
   ▼
web/src/index.ts             ← 只做「传输 + 会话」，不含 agent 逻辑
   │  调用 runAgent(history, message, onEvent)
   ▼
core/src/agent.ts            ← 与 CLI 完全共享
   ├─ llm.ts（模型 + SSE 解析）
   └─ tools.ts / location.ts（工具）
```

**核心结论**：`runAgent` 的第三个参数 `onEvent` 就是那个接缝。
CLI 版把它接到 `process.stdout.write`，Web 版把它接到 HTTP 响应流。
交互形态的差异，全部收在这一层。

## 3. 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 返回 `public/index.html` 单页面 |
| POST | `/api/chat` | 请求体 `{ message: string }`，响应为 SSE 流 |

### SSE 事件协议

每条事件格式固定：`event: 名称\ndata: JSON\n\n`（两个换行结尾）。

| event | data | 前端动作 |
| --- | --- | --- |
| `text` | `{ chunk: string }` | 追加到当前气泡 |
| `tool` | `{ phase: 'start', name, args }` | 显示 `→ 工具名(参数)` |
| `tool` | `{ phase: 'end', name, output }` | 显示 `← 结果摘要` |
| `error` | `{ message: string }` | 显示红色错误条，不中断页面 |
| `done` | `{}` | 收尾，解锁输入框 |

## 4. 关键设计决策

**为什么用 SSE 而不是 WebSocket**
数据是单向的（服务端 → 浏览器），SSE 用普通 HTTP 就能实现，浏览器端不需要额外协议、
不需要心跳、断线重连语义也简单。WebSocket 是双向长连接，这里是过度设计。

**为什么不用 `EventSource` 而用 `fetch` 读流**
`EventSource` 只支持 GET，无法提交消息体。所以前端用 `fetch` + `response.body.getReader()`
自己解析 SSE——这也顺便让你理解「SSE 本质就是一段按格式写的文本流」。

**为什么 agent 循环放在服务端**
API Key 绝不能下发到浏览器。同时循环、重试、工具执行都在可信环境里。

**为什么会话只用一份内存数组**
单用户学习 demo。多用户需要按 `sessionId` 分桶 + 过期清理，属于下一步。

**为什么前端零框架**
原生 DOM + 原生 `fetch` 即可。这个项目的学习目标不是前端工程化。

## 5. 明确不做

- 不做多用户会话隔离、不做登录鉴权
- 不做消息持久化（重启即清空）
- 不做 Markdown 渲染（纯文本）
- 不引入 React/Vue/任何前端构建工具

## 6. 启动

```bash
cd code/web
node src/index.ts          # 默认 http://localhost:3000
```

配置与 CLI 共用 `code/.env`。端口可用 `PORT=8080` 覆盖。

## 7. 验收标准

- **AC-W1** 打开 `http://localhost:3000` 能看到输入框和提示文案
- **AC-W2** 输入「明天天气」，气泡里依次出现定位、天气两条 `→ / ←` 记录，最后流式输出中文回答
- **AC-W3** 回答过程中输入框禁用，结束后自动恢复并聚焦
- **AC-W4** 停掉服务或断网时，页面显示红色「连接失败」而不是白屏
- **AC-W5** API Key 不出现在任何前端代码或响应中（检查页面源码与网络面板）
